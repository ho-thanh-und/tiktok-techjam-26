# Running the agent and reading the results

Every command here has been run on this repository. Expected output is quoted so
you can tell a healthy run from a broken one.

The single most important thing to get right is **which of the three tracks you
are on**, because they measure different tasks and their numbers are not
comparable. Start there.

---

## The three tracks

| Track | Config | Label | Metrics | Data | Status |
|---|---|---|---|---|---|
| **Demo** | `configs/demo.json`, `configs/demo-llm.json` | `is_click` | NDCG@10, Recall@50 | synthetic, 20 users x 80 items | plumbing test only |
| **Public research** | `configs/kuairand-public-research.json` | `is_click` | NDCG@10, Recall@50 | real KuaiRand-Pure | closest runnable proxy |
| **Competition** | `configs/competition.example.json` | `is_click` | NDCG@10, Recall@50 | organizer-supplied | fails closed until assets arrive |

A fourth, **legacy** track exists: `baseline.py` / `evaluate.py` / `submit.py` and
`examples/kuairand_competition_benchmark.py` implement the original `long_view`
+ GAUC/nDCG@5 protocol. README line 35 states it "does **not** match the current
competition contract and must not be used as the official baseline." Its numbers
(FM primary = 0.5946) are **not** comparable to any of the three tracks above.
Use it only if you deliberately want the legacy ladder.

## Setup

Python 3.11+. The control plane has no dependencies; the legacy scripts need numpy.

```bash
python --version          # 3.11 or newer
pip install numpy         # only for baseline.py / evaluate.py / submit.py
```

For the real-data tracks, fetch the dataset (~1.4M log rows):

```powershell
powershell -File scripts/fetch_kuairand_pure.ps1
```

It downloads from Zenodo, verifies MD5 `0820331067a3784d9691136f772b35a7`, and
extracts to `KuaiRand-Pure/data/`. No registration needed.

For the LLM planner, put your key in the git-ignored root `.env`:

```dotenv
SOC_API_KEY=your_real_key_here
```

The key is read only at planner-subprocess launch. It never enters config JSON,
command arguments, the EvidencePack, run artifacts, or reports.

## Always preflight first

```bash
python -m automl_agent --config configs/demo-llm.json preflight
```

Validates the contract, checks every declared asset exists and matches its
checksum, and confirms the API key is present. Look for:

```json
"valid": true,
"errors": [],
"planner": { "mode": "llm", "provider": "soc", "api_key_configured": true }
```

`"api_key_configured": false` means `.env` was not found or the variable is
empty. Fix that before running — a run would otherwise fail at decision 1.

## Track 1 — Demo (fastest check that everything works)

Deterministic planner, ~3 seconds:

```bash
python -m automl_agent --config configs/demo.json run --run-id demo-001
```

LLM planner driving each decision, ~20 seconds and ~7,500 tokens:

```bash
python -m automl_agent --config configs/demo-llm.json run --run-id llm-001
```

Both print a summary on stdout:

```
Run llm-001 - completed (converged)

                  score       NDCG@10     Recall@50
  baseline     0.447178      0.265691      0.628666
  final        0.846365      0.761424      0.931306
  delta       +0.399187

   1  category_affinity               promoted     0.846365
   2  hybrid_affinity_popularity      rejected     0.824993
   3  shrinkage_popularity            rejected     0.447178
   4  noise_control                   rejected     0.440981

  4 iterations - 20.6s compute - 7270 LLM tokens
```

**Do not read the demo numbers as model quality.** The data is generated by
`demo_benchmark.probability()`, where click probability is set almost entirely by
category match (0.72–0.92 for the preferred category, 0.03–0.08 otherwise). The
winning strategy `category_affinity` scores by exactly that quantity, so it *is*
the generative model. Scoring the validation set with a perfect oracle gives
primary **0.841047** — the agent's 0.846365 is at the ceiling. Meanwhile
`official_baseline` ranks by popularity, which sees only a tiny quality term, and
lands just **+0.006** above the random control.

The demo proves the orchestrator, planner, retry, and promotion logic work. It
says nothing about recommender quality.

### Telling the two planners apart

`0 LLM tokens` means the deterministic planner ran — check you used
`demo-llm.json`, not `demo.json`. Every experiment record stamps `planner_mode`:

| Value | Meaning |
|---|---|
| `command` | deterministic `planner_cli` policy |
| `llm` | the model chose this experiment |
| `catalog_fallback` | LLM was configured but failed; deterministic policy took over |

## Track 2 — Public research (real data)

~60 seconds on real KuaiRand-Pure logs:

```bash
python -m automl_agent --config configs/kuairand-public-research.json run --run-id real-001
python -m automl_agent --config configs/kuairand-public-research.json report real-001
```

Last measured:

```
baseline           0.789617
user_tab_affinity  0.791694   +0.002077   promoted
hybrid_context     0.790805   +0.001188   rejected
author_context     0.789491   -0.000126   rejected
```

**Read this gain with suspicion.** The agent selects the best of N on the
validation split and then reports that same split's score. There is no held-out
test, and no seed-variance estimate for this pipeline. A +0.002 best-of-3 result
is exactly the shape that selection bias produces from noise. Treat it as "not
yet distinguishable from the baseline" until it is confirmed on a held-out split.

## Reading the results

Four views of the same run, cheapest first:

```bash
# 1. Summary — printed automatically when a run finishes
python -m automl_agent --config <cfg> run --run-id <id>

# 2. Markdown report — metrics table, experiment ladder, resource use, SHA-256
python -m automl_agent --config <cfg> report <id>

# 3. Full state — ~170 lines of JSON, every attempt and log path
python -m automl_agent --config <cfg> status <id>

# 4. Dashboard — browse all runs at http://127.0.0.1:8765
python -m automl_agent --config <cfg> serve --port 8765
```

`run` and `resume` accept `--json` to print the full state instead of the summary,
for scripting.

### What is on disk

Under `artifacts/agent_runs/<run-id>/`:

| Path | Contents |
|---|---|
| `state.json` | resumable run state; the source of truth |
| `events.jsonl` | structured audit trail; `experiment_started` carries the planner's reason, evidence, and hypothesis |
| `final_submission.csv` | the deliverable, byte-identical to the winning experiment's submission |
| `final_manifest.json` | SHA-256, stop reason, hidden-test evaluation count |
| `experiments/NN-<id>/record.json` | per-experiment proposal, metrics, promotion decision, interpretation |
| `planner/decision-NN/evidence.json` | the exact EvidencePack sent to the planner |
| `planner/decision-NN/decision.json` | the decision returned |
| `*/execution/attempt-N/` | child-process stdout, stderr, heartbeat, kept per attempt |

Progress lines go to **stderr**, results to **stdout** — so `2>/dev/null` gives
you just the summary, and `1>/dev/null` gives you just the live progress.

### Interpreting a stop reason

| `stop_reason` | Meaning |
|---|---|
| `converged` | no material improvement for `patience` iterations (epsilon 0.002, patience 3) |
| `experiment_catalog_exhausted` | every catalog experiment has been tried |
| `iteration_budget` / `wall_clock_budget` | budget cap reached |

## Interrupted runs

State is written atomically after every step, so a killed run resumes exactly
where it stopped:

```bash
python -m automl_agent --config configs/demo-llm.json resume llm-001
```

An experiment that was mid-flight is recorded as `failed` with
`failure_class: "interrupted"`, and the run continues from the next decision.
Resuming a finished run is a safe no-op. Reusing a run id with `run` is refused —
use `resume`.

## Troubleshooting

**`finish_reason='length'` from the SoC planner.** `qwen3.8:27b` is a reasoning
model whose chain-of-thought is charged against `max_output_tokens`, so a modest
budget is spent entirely on thinking and no JSON is ever emitted. The planner
sends `enable_thinking: false` by default, which fixes it. To re-enable
reasoning, set `"enable_thinking": true` in the planner block — this requires
`max_output_tokens` of at least 4000 and roughly quintuples planner latency.

**A planner failure kills the whole run.** `demo-llm.json` sets
`fallback_to_catalog: false`, so a completed run proves the LLM drove every
decision. Transient faults (HTTP 429/500, connection drops) still self-heal via
one automatic retry. Permanent faults (malformed JSON, truncation, sustained
outage) stop the run by design. For a long unattended run set
`"fallback_to_catalog": true` — the fallback picks from the same reviewed
catalog and stamps `catalog_fallback` on the record, so the audit trail always
shows when the LLM was not driving.

**`is not valid JSON`.** A child process was killed mid-write. The message names
the file; delete it and re-run, or `resume`.

**Baseline mismatch aborts the run.** `official_baseline.expected_metrics` did
not reproduce within `tolerance`. This is the contract gate working — investigate
the drift rather than loosening the tolerance.

## Legacy protocol

Only if you specifically want the original `long_view` + GAUC/nDCG@5 ladder.

```bash
python baseline.py --model fm       # valid primary 0.6015 | test 0.5953
python baseline.py --model pop      # valid 0.5807 | test 0.5715
python baseline.py --model random   # valid 0.4827 | test 0.4757
```

The random row is a harness self-check: if test primary is not ~0.475 (+/-0.001),
something is broken. Score your own submission (valid only — test labels are
held out):

```bash
python submit.py --score --split valid submission.csv
python submit.py --check --split test  submission.csv
```

`examples/kuairand_competition_benchmark.py` wraps this protocol in the agent
contract. It scores the valid split only, so test is never consumed, and reports
per-seed variance:

```bash
python examples/kuairand_competition_benchmark.py run \
  --strategy official_baseline --cache .splits.pkl \
  --result result.json --submission submission.csv
```

Reproduces the published FM baseline exactly: valid primary **0.601469**.
Strategies: `official_baseline`, `fm_k32`, `fm_k8`, `fm_lr_higher`,
`fm_seed_ensemble`, `fm_user_features`, `fm_pop_blend`, `pop_control`,
`random_control`. First run ~75s, subsequent ~65s with `--cache`.

No agent config points at this adapter yet; it runs standalone only.
